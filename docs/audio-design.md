# 音频设计规格 · 轮回渡口（Lunhui Dukou）

> 文档状态：**v1（P1/P2 落地）** ｜ 维护：音频总监（audio-director）
> 关联文档：`docs/art-style-standard-2.5d.md`（视觉/「沉默三秒」时序）、`packages/web/src/audio/audio.ts`（引擎实现）、`packages/web/src/audio/useAudio.ts`（React 绑定）
> 适用范围：Web 演出层（`@lunhui/web`），引擎内核 `@lunhui/engine` 的 `pause:true` / `isKey=true` 为音频触发源。

---

## 0. 听觉身份（Audio Identity）

一句话：**雨夜渡口里，一盏汤碗的暖光是唯一会发声的「在场」。** 全作音频以「减法」为美学——大量留白、极轻的在场感、只在关键真相处点一声克制回响。

| 维度 | 取向 |
|---|---|
| 核心氛围 | 雨夜渡口 · 轮回 · 悬疑 · 记忆 |
| 情绪主色 | 冷蓝压暗 + 唯一暖光（与视觉 §3 同源） |
| 听觉留白 | 「汤主沉默三秒」是核心节奏（详见 §4） |
| 音色原则 | 程序化生成优先（Web Audio 原生），零外部音频文件依赖 |
| 禁忌 | 无史诗 BGM、无写实环境铺满；避免高饱和、明亮、密集的音响 |

---

## 1. 音乐基调（Music Tone）

本作**无传统线性 BGM**，采用「持续音床 + 事件点效」的极简动态模型：

- **常态（审问/试探）**：雨声床（程序化滤波白噪声）+ 汤碗暖光 pad（在场感）双层叠加，信息密度低、留白多，对应视觉「悬疑段」（冷蓝压暗 + 收紧 vignette + 粒子雨）。
- **回响段（命中真相/记忆涌现）**：触发「沉默三秒」，雨声骤弱、暖光 pad 压暗保留，一声克制的钟鸣泛音（`playReveal`）标记转折，记忆碎片叠影浮现。
- **释然段（代价/过渡）**：雨声与暖光同步缓回，进入下一碗汤。

**情感曲线对齐视觉（art-style §2.2）：**

```
悬疑(审问) ──→ 回响(命中 isKey) ──→ 释然(沉默后过渡)
 冷蓝+雨床        暖光收束+留白        雨声渐回
```

## 2. 音效设计（SFX Design）

所有音效由 `audio.ts` 程序化生成，无外部文件。下表为设计意图与实现映射。

| 音效 | 触发 | 设计意图 | 引擎方法 / 实现 |
|---|---|---|---|
| **雨（环境床）** | 全程常驻 | 雨夜渡口的基底存在感；可随「悬疑度」调密度 | `start()` 内白噪声 BufferSource → 低通(1800Hz) → 增益(0.16) → 主总线；LFO(0.07Hz, ±0.05) 做缓慢起伏 |
| **汤碗暖光 pad** | 全程常驻（极轻） | 「在场感」——玩家始终在汤主身边 | sub 正弦 65Hz + 三角波 98Hz，增益 0.045，经主总线 |
| **钟鸣 / 水波（命中）** | 命中关键真相 `isKey=true` | 克制的一声回响，制造情感冲击峰值 | `playReveal()`：C5 基频 + 两个非整数泛音(×2.01, ×2.99)，低通 4k，短促包络(~1.6s 衰减) |
| **否定音（被否决）** | 玩家偏离 / 选错 / 被居民否定 | 低沉下行的「不对」信号 | `playReject()`：正弦 140→70Hz 下行，增益 0.3，~0.5s |
| **沉默留白** | 见 §4 | 「汤主沉默三秒」音频化 | `setSilence(true)`：雨声→0.012、pad→0.03（保留压暗），`setTargetAtTime` 平滑过渡 |
| **渡船** | （预留）轮回/转场 | 水面涟漪脉冲（与视觉 §4.3 涟漪联动） | 预留 `playReveal` 复用或后续扩展事件；当前版本以 `playReveal` 兼做「水声点」 |

> 渡船/水面作为「事件点效」的视觉-听觉联动点：命中真相时除 `playReveal` 钟鸣外，建议同步触发视觉涟漪脉冲（art-style §4.3），形成「一声钟鸣 + 一圈涟漪」的复合回响。

## 3. 调色板与混音总线（Mix Bus）

```
[雨声床] ─┐
[暖光pad] ─┼─→ [Master Gain] ─→ destination
[事件点效]─┘   (受 setMuted 控制)
```

- **Master Gain**：基准 0.85；`setMuted(true)` 平滑归 0（硬静音，区别于沉默留白）。
- **沉默留白**只作用于雨声/暖光子总线，不碰 Master，因此释然后能无缝回升。
- 所有增益变化一律经 `setTargetAtTime` / 短 `linearRamp` + `ctx.currentTime` 调度，**杜绝爆音**。

## 4. 「沉默三秒」音频化时序（核心节奏）

触发源：引擎返回 `pause:true`（即 `isKey=true` 命中）。与视觉标准 `SILENCE_MS = 2800`（区间 2500~3000）严格对齐。

| 阶段 | 时序 | 音频动作 | 视觉联动（art-style §5.1） |
|---|---|---|---|
| T0 命中 | 0 ms | 文本结束；若需要，预置 `playReveal` 在收束点触发 | 立绘切 `face_hit` |
| T1 收束 | 0–500 ms | 调 `setSilence(true)`：雨声 0.16→0.012、暖光 pad 0.045→0.03（过渡 ≈448ms = SILENCE_MS×0.16，落进本窗口内与暖光收束同帧）；暖光收束同步一声低频「水声点」 | 冷蓝淡出至 ~20%，暖光收束（§4.2） |
| T2 沉默 | 500–2800 ms | **汤主沉默三秒**：仅保留压暗的暖光 pad + 近乎静默的雨声；无点效、无输入 | 无文本/输入，镜头微推，记忆碎片叠影淡入（§4.4） |
| T3 回落 | 2800–3600 ms | 调 `setSilence(false)`：雨声/暖光平滑回升至常态 | 暖光回落，冷蓝回归，允许继续输入 |

**衔接约定（给工程负责人）：**

```ts
// 命中 isKey 时（App 在收到 pause:true 后）：
engine.setSilence(true);   // 进入沉默三秒
// SILENCE_MS 后（由演出层计时器驱动）：
engine.setSilence(false);  // 退出沉默三秒
```

> **缩放契约（校准 #2）**：音频过渡时长 = `silenceMs × 0.16`，由 `createAudioEngine({ silenceMs })` 透传。演出层须把**已缩放**的 `SILENCE_MS`（移动端 3000 / 演出减速 ×1.5 → 4200）传给 `silenceMs`，音频过渡即随之缩放，与暖光收束窗口始终同步。

演出层**必须预留 `onSilenceStart / onSilenceEnd` 钩子**（art-style §5.4），音频在这两个钩子里切换 `setSilence`，确保音画同帧。

## 5. 动态音频 × LLM 生成节奏的衔接约定

本作对话由 LLM 生成、演出层用打字机节奏呈现（art-style §5.2）。音频须与「文本生成/打字机」节奏解耦但呼应：

1. **打字机不驱动点效**：`playReveal` / `playReject` 仅由语义事件（`isKey` / 否定标记）触发，不由字符流触发，避免噪声化。
2. **标点停顿 = 微呼吸**：可在句号/问号停顿处让雨声 LFO 轻微加深（可选），但默认保持平稳，留白优先。
3. **节奏倍率联动**：art-style §6.5「演出减速 ×1.5」开关应同步作用到 `SILENCE_MS` 与 `playReveal` 衰减时长（建议 `REVEAL_DUR` 随之延长），保证音画同步放缓。其中沉默过渡通过 `createAudioEngine({ silenceMs })` 透传缩放后的 `SILENCE_MS` 自动跟随，无需单独调参。
4. **手持回退**：LLM 超时/失败时，演出层应保留环境音床不中断，仅跳过事件点效——音频绝不应因生成失败而静默或报错（引擎全程 guard，缺 AudioContext/未 start 均 no-op）。

## 6. 性能预算（Performance Budget）

对齐 art-style §8.2（并发音频数 ≤ 8）。本模块为纯程序化生成，内存/节点开销极低。

| 指标 | 预算 | 说明 |
|---|---|---|
| 常驻音频节点数 | ≤ 6 | 雨声链 3（source/filter/gain）+ LFO 2（osc+gain）+ 暖光 3（2 osc + gain）+ master 1；总计约 9 个常驻节点，远低于浏览器单上下文上限 |
| 瞬时点效并发 | ≤ 3 | `playReveal`（3 osc）/`playReject`（1 osc）短促自清理（onended 断开），不累积 |
| 并发音频声部（Web Audio） | ≤ 8 | 环境(雨+暖光) + 事件点效，沉默段渐弱释放余量 |
| 首屏音频开销 | ~0 KB | 无外部音频文件，全部程序化生成；仅 AudioContext 惰性创建 |
| 触发延迟 | < 30 ms | 点效以 `ctx.currentTime` 即时调度，无加载等待 |
| 自动播放合规 | 必须 | `start()` 由用户手势（点击「开始」）触发；`useAudio` 在 enable 后创建引擎，App 于手势中调用 `start()` |

**优化建议（若后续扩展）：**
- 多居民差异化音色用同一组振荡器参数微调，而非新增常驻节点。
- 长局游玩后若发现节点泄漏，确认每次 `playReveal`/`playReject` 的 `onended` 均已断开（已实现）。
- 移动端（Capacitor）默认 `SILENCE_MS` 取上限 3000ms（art-style §7.3），音频过渡 TC 同步放宽。

## 7. 验收清单（Audio QA）

1. [ ] 全场景常驻雨声床 + 暖光 pad，无静默死区（除非显式 `setMuted`）。
2. [ ] 命中 `isKey=true` 必触发 `setSilence(true)` 且雨声降至 ≈0.012、暖光保留压暗。
3. [ ] 沉默三秒时长 ∈ [2500, 3000]ms（默认 2800），与视觉 `SILENCE_MS` 一致。
4. [ ] `playReveal` 克制短促，无爆音；`playReject` 低沉下行。
5. [ ] 所有增益过渡经 `setTargetAtTime`/ramp，无咔哒声。
6. [ ] 缺 AudioContext（测试/SSR）时引擎全部 no-op，不抛错。
7. [ ] 组件卸载 / `enabled=false` 时 `dispose()` 关停并 `close()` context，无泄漏。
8. [ ] 无新增 npm 依赖，纯 Web Audio 原生实现。
